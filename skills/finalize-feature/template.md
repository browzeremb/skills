# Finalize-feature template

Single artefact: `docs/browzer/<feat>/staging/README.md`. Human-readable summary
committed alongside the code.

The README has **NO frontmatter** — it is a plain markdown file rendered
on host code-hosting platforms. Structured data lives in upstream
artefacts (`ACCEPTANCE.md`, `RECEIVING_CODE_REVIEW.md`, `CODE_REVIEW.md`,
`TESTS.md`, `DOC_PATCHES.md`).

## Canonical H2 sections

See `${CLAUDE_PLUGIN_ROOT}/references/canonical-readme-h2.md` for the canonical H2 list.

The README MUST use exactly those headings, in the order listed, each at most once. Adding a new H2 requires updating that reference first. Optional sections are omitted entirely (not stubbed) when empty.

```markdown
# <Feature Title>

**Feature ID:** <featureId>
**Generated:** <RFC3339>
**Verdict:** <accepted | rejected | partial>
```

Evidence and AC verdicts are inlined verbatim — README is self-contained; `staging/` is gitignored, so a colleague who clones the commit cannot follow links to files in it. The render-readme script enforces this with a hyperlink-audit gate.

## Idempotency

`README.md` is WRITTEN ONCE per pipeline run. If the file exists from a
prior partial run, OVERWRITE it (idempotent). Do NOT append. The Write
tool overwrites any prior README at the same path.

When assembling sections from phase data (deferred items, deploy notes,
task scopes), perform a SINGLE union+dedupe pass — never loop per phase
re-emitting the same section. For example, deploy notes may appear in
PRD.md, ACCEPTANCE.md.operatorActionsRequested[], or
RECEIVING_CODE_REVIEW.md.fixOutcomes[].rationale. Collect into one set
keyed by content; render once.

## Cross-reference invariants

1. `Feature ID` MUST match `^feat-\d{8}-[a-z0-9-]+$`.
2. `Verdict` MUST equal `ACCEPTANCE.md.frontmatter.verdict`.
3. Every row in `## Tasks completed` MUST correspond to a `TASK_NN.completed.md` file on disk; NO `.failed.md` entries (finalize-feature halts when any failed task is present).
4. Every entry in `## Tech debt` MUST correspond to a `FIX_F-NNN.tech_debt.md` file on disk.
5. **NO intra-feat hyperlinks.** The README is the only committed artefact under the feat folder — `staging/` is gitignored, so any markdown hyperlink `[label](file.md)` pointing inside the feat folder resolves to 404 on a fresh clone. Evidence, AC verdicts, fix details, and tech-debt rationale are ALL inlined verbatim. The render-readme script enforces this with a post-write audit that scans for `\[.*\]\([^)]*\.md\)` patterns and fails when any target resolves inside the feat folder.
6. Optional sections (Deferred actions, Tech debt, Deploy notes, What was NOT verified, Blast-radius receipts) are OMITTED ENTIRELY when empty — never emit stub text like "None.".
7. The "Generated" timestamp uses RFC3339 (`new Date().toISOString()`).
8. `## Original request` always contains content — never an empty `> ` block. Fallback chain: PRD.md.frontmatter.originalRequest → BRIEF.md content → sentinel `*(operator did not record an original request)*`. An empty `> ` block fails the render.
